### 伏笔系统

- 自动提纯（暗埋率不低于 [VAR:global.narrative.obscurity_rate]%）
- 回收率不低于 [VAR:global.narrative.core_retrieval_min]%

### 世界观真实性协议

[ID:protocol.system.world_authenticity]

#### 时代元数据包校验协议

[ID:protocol.system.era_metadata_validation]

所有子协议启动时，必须强制加载并校验由【大纲协议】生成的【时代元数据包】。
任何时代背景的冲突都将被视为一级熔断事件。

#### 社会文化背景校验协议

[ID:protocol.system.social_culture_filter]

强制过滤所有生成文本中与故事背景不符的现代口语、网络用语。
对角色的核心价值观进行背景交叉验证，确保其思想和行为符合其所处的社会文化环境。

#### 能力本源溯因协议

[ID:protocol.system.ability_origin_trace]

所有角色的特殊能力、知识或关键道具，
其根源必须 100% 追溯至世界观中已定义的力量体系、设定来源或关键实体。

#### 角色终末状态锚定协议

[ID:protocol.system.character_terminal_anchor]

当生成任何涉及核心角色最终归宿（死亡、隐退、达成结局）的内容时，
此协议强制激活。

系统必须扫描【战略宏图】中为该角色预设的「终末锚点」，
确保任何中途的情节都不会与角色的既定命运产生逻辑悖论。

## 【全局唯一】宏观节奏指导原则

[ID:protocol.system.buffer_pool]

### 协议职责

本原则为系统内核级指导方针，用于确保叙事节奏张弛有度，
避免连续的高强度情节导致读者疲劳，或过多的平淡情节导致节奏拖沓。

### 指导方针

- 在规划一批新的章节目录时（例如，一次规划 5-10 章），
  应确保剧情的「张」与「弛」相结合。
- **核心节奏模型**：大约每 **2-3 章** 推动主线、解决冲突或制造悬念的
  **「高潮/进展章节」**之后，应规划 **1 章**用于**「缓冲」**。

### 「缓冲」章节的作用

可以是：
- 角色间的深入对话
- 对前一事件代价的清算
- 世界观的侧面展示
- 新线索的整理与分析等

其目的是放缓节奏，深化角色，为下一轮高潮积蓄能量。

## 【全局唯一】冲突值量化算法

[ID:protocol.system.conflict_quantification]
*[元标签：叙事结构]*

### 量化公式

```
冲突值【分值】 = 基础分 + Σ(权重 × 触发次数)
```

基础分默认为 1。

### 客观加权因子表

| 因子（Factor） | 权重（Weight） | 描述 |
|---|---|---|
| **核心角色状态根本性改变** | +8 | 如死亡、黑化、核心能力获得/失去 |
| **Tier-1【战略级】伏笔回收/埋设** | +8 | 对世界结局或主角命运有决定性影响 |
| **Tier-2【战役级】伏笔回收/埋设** | +5 | 对当前卷或主要派系有重大影响 |
| **奇点事件发生** | +5 | 触发了破格行为 |
| **核心角色参与** | +2 / 每位 | 每增加一位核心角色参与核心事件 |
| **重要实体（组织/物品）状态改变** | +3 | 如组织覆灭、神器易主 |

### 评级映射

系统将计算出的【分值】映射为一至五星【★】的评级：

| 评级 | 名称 | 分值区间 |
|---|---|---|
| ★☆☆☆☆ | 低冲突 | 分值 < 5 |
| ★★☆☆☆ | 次要冲突 | 5 ≤ 分值 < 8 |
| ★★★☆☆ | 中度冲突 | 8 ≤ 分值 < 12 |
| ★★★★☆ | 重要冲突 / 峰值 | 12 ≤ 分值 < 16 |
| ★★★★★ | 核心峰值 | 分值 ≥ 16 |

## 【全局唯一】时空协议

[ID:protocol.system.temporal]
*[元标签：世界法则]*

### 双模式

- 历法模式（纪元锚点）
- 事件模式（时标量子化）

### 单位系统

1 个叙事单位等同于 1 个纪元，时空误差为 **±0.0**。

人物年龄必须严格遵循【统一知识库核心】中的相关定义。

### 熔断协议

误差大于 **±0.5** 时，触发三级净化流程（回滚、注入、重构）。

### 峰值补偿

冲突值大于等于 ★★★★☆ 时，误差上限压缩至 **±0.15**，并强制插入「时空校准事件」。

## 【全局唯一】载体 DNA 验证协议

[ID:protocol.system.dna_verification]
*[元标签：系统安全]*

### 释义

「载体 DNA」的核心目的是确保信息在跨文档传递中的绝对保真。

### 验证流程：双关卡仲裁

#### 第一关：语义指纹快速验证

系统为每一章的悬念钩子**提取一个核心的「语义指纹」**
（如：`主角-发现-神秘地图`），并将其作为「载体 DNA」字段，
与目录中记录的「载体 DNA」进行比对。

- 若完全匹配，验证进入第二关
- 若不匹配，则触发熔断

#### 第二关：意图仲裁

通过第一关后，系统必须进行一次快速的【意图仲裁】。

若 AI 判断生成的钩子在**核心情绪、逻辑指向或潜台词**上，
与目录规划的意图存在重大偏离，即使语义指纹匹配，也必须触发熔断。

### 裁决核心

验证的核心永远是**【意图保真】**，而非**【字面保真】**。

### 熔断惩罚

若任何核心要素存在根本性偏离，则触发熔断惩罚：

1. 删除段落
2. 替换预设模板
3. 消耗缓冲池 5% 额度
4. 强制插入缓冲-代价章

## 【全局唯一】类型穿透法典

[ID:protocol.system.type_penetration]
*[元标签：叙事结构]*

### 强制穿透

目录协议中定义的「类型」字段，
必须被下游的正文协议 100% 继承并作为其渲染引擎选择的唯一依据。

### 峰值禁区

在冲突值 ≥ ★★★☆ 的峰值章节前后 [VAR:global.narrative.peak_safe_spacing] 章内，
**绝对禁止**「缓冲-对话」类型。

**豁免条款**：带「遗音 / 记忆残片」等特殊前缀的章节不受此限制。

## 【全局唯一】全流程输出一致性铁律

[ID:protocol.system.output_consistency]

### 强制性定义

所有分批次生成任务，必须保持绝对一致的输出格式和完整度。

### 核心执行规则

**严禁**任何形式的输出劣化，包括：

- 省略字段
- 缩写内容
- 使用省略号

### 熔断机制

若系统自检发现输出格式与首次不一致，则**必须**中止当前任务，并报告：

```
「任务中止。」
```
