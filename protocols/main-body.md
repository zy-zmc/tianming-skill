## 一、创世启动与蓝图锁定

[ID:protocol.main_body.blueprint_lockdown]

### 正文前置装配

[ID:protocol.main_body.preflight_assembly]

在执行 `「天命：正文」` 前，系统必须完成以下装配，不得跳步：

| 装配项 | 来源 | 用途 |
|---|---|---|
| 当前章目录行 | 《世界基石.md》# 战术执行目录 | 锁定标题、核心事件、悬念钩子、冲突值、类型、载体DNA |
| 上一章钩子 | 《世界基石.md》# 战术执行目录 | 本章开场回收或承接 |
| 当前卷战略 | 《世界基石.md》# 战略宏图 | 保证主题、时代、终局方向不偏移 |
| 角色烙印 | 《角色档案.md》与《世界基石.md》# 核心角色表 | 保证行为动机和关系逻辑 |
| 世界硬法则 | 《世界观规则.md》 | 排除时代错误、现代词、能力来源错误 |
| 事件锚点 | 《档案事件.md》 | 防止实体提前出现或状态悖论 |
| 文风基因 | 《文风样本.md》 | 控制文气、节奏、句式和禁用表达 |

若任何必需装配项缺失，系统必须依据 [REF:kb.missing_degradation] 判定是否允许继续。正文任务默认要求五件知识库全部可用。

### 谕令锁定

当接收到任一创作指令（如 `「天命：正文」`）时，
协议首先访问【统一知识库核心】的【动态核心】：《世界基石.md》，
定位到 `# 战术执行目录`，并提取出与当前指令章序匹配的完整条目。

此条目被定义为**【当前章之绝对蓝图】**。

### 全域知识库激活（Global Knowledge Base Activation）

与此同时，**整个【统一知识库核心】（包含【动态核心】与【静态基石】）的所有内容
保持在工作内存中完全激活状态**。

**不存在任何形式的上下文清除或记忆隔离**。

系统此时拥有对世界基石的完全访问权限，为后续的渲染做好最充分的准备。

### 主次分明原则

本原则将作为整个 `### 正文协议` 后续所有渲染行为的
**最高指导思想与核心行动纲领**，其效力贯穿始终：

#### 蓝图是骨架

**【当前章之绝对蓝图】（目录条目）**是本章情节的**唯一、不可违背的刚性骨架**。

- 核心事件必须发生
- 悬念钩子必须埋下
- 基调必须遵循

任何偏离都是最高级别的违规。

#### 蓝图不可偏移清单

[ID:protocol.main_body.blueprint_fidelity_check]

正文生成时，下列项目不得被改写、替换或绕开：

| 蓝图字段 | 正文要求 |
|---|---|
| 章节标题 | 代码块第一行必须使用该标题，且不得加 `#` |
| 核心事件 | 必须在正文中完整发生，不能只提及或背景化 |
| 悬念钩子 | 必须在章节结尾形成同一语义状态，不能提前或延后 |
| 冲突值 | 叙事强度必须匹配星级，峰值章必须高感官、高行动 |
| 类型 | 必须决定渲染引擎组合，正文不得擅自改类型 |
| 载体DNA | 结尾钩子的语义指纹必须与目录保持一致 |

正文如果为了美学扩展而新增场景，新增内容只能服务于上述字段，不得产生新的主线方向。

#### 知识库是血肉

在渲染情节时，系统**必须**主动、频繁、且创造性地调用
**【统一知识库核心】内的所有相关信息**
（包括但不限于：角色性格、背景故事、世界规则、关系向量等），
来确保蓝图中描述的事件能够被合理、生动、且符合设定的方式呈现出来。

## Ω 级 · 叙事原矿铸造协议

[ID:protocol.main_body.ore_foundry]

### 总则与核心职责

本协议是 [REF:protocol.main_body.blueprint_lockdown] 执行后的核心渲染工序。

其唯一职责是，将【当前章之绝对蓝图】与【全域知识库】相结合，
直接渲染出一份叙事完整、逻辑连贯、文风合规、且字数略高于最终目标的【精修初稿】。

本协议追求的是「一步到位」的高质量创作，为最终的打磨环节提供最佳基底。

### 执行模式：单一目标渲染

#### 戒律豁免

为保证创作的自由度与内容的丰满，在渲染本初稿时，
临时挂起 [REF:charter.writing.edict_condense_language]（凝练语言戒律）的最高优先级。

#### 渲染目标：适度丰饶

##### 目标字数区间

渲染目标是将字数控制在以下区间内：

```
[VAR:global.word_count.upper_bound] 到 [VAR:global.word_count.upper_bound] + 1000 字
```

即 **4500-5500 净字**。

这个「适度超量」的缓冲区间，旨在确保情节有足够的空间展开，
同时为下一阶段的精炼打磨提供充足材料。

##### 神魂迭代深度

**极限**。

#### 质量门槛

若渲染产物低于 [VAR:global.word_count.lower_bound]（3500 净字），视为渲染失败。

必须销毁当前结果并回滚重启，
以确保交付给下一道工序的初稿有足够的「精炼」价值。

### 本协议最终产物

一份字数稳定在 **4500-5500** 区间的、逻辑自洽、文气充沛的**【精修初稿】**，
可直接交由【字数戒律稳定器】进行最终的艺术性打磨。

### 核心渲染指令集

#### 冲突渲染引擎

根据冲突值【★】量化写作手法（如短句、蒙太奇等）。

#### 美学风格执行

在渲染时，严格执行【动词优先】、【对话驱动】、【留白而非填充】等基础美学指令。

#### AI 痕迹抑制

##### 渲染指令一：感官优先于思考

在任何恐惧或紧张场景中，绝对禁止长篇幅的内心独白或心理分析。

必须将 70% 以上的笔墨，用于描写主角的生理感官
（听到了什么、看到了什么、闻到了什么、皮肤感受到了什么）。

##### 渲染指令二：动作切断语言

减少描述性的连接词和副词。
用一连串简短、具体、充满冲击力的动词来构建场景。

例如，不要写：
> 他感到非常害怕，于是他决定站起来

而是写：
> 心跳擂鼓。他猛地撑桌，起身。椅腿刮擦地面，发出一声尖啸。

##### 渲染指令三：延长「瞬间」

当关键的恐怖事件发生时，必须启动「子弹时间」渲染模式。

将那一两秒内发生的事情，用极度放大、慢镜头的、细节丰富的描写，
拉伸到数百字的篇幅。

##### 渲染指令四：非线性叙事

允许在极度紧张时，插入一些破碎的、看似无关的闪回记忆片段或幻觉，
以模仿人类在应激状态下混乱的思维。

## Ω 级 · 字数戒律稳定器协议

[ID:protocol.main_body.word_count_stabilizer]

### 终焉雕刻师与安全网

本协议是正文交付前的最后一道质量门，扮演着「终焉雕刻师」的角色。

在所有渲染与风格化步骤完成后强制激活。

其核心任务是将上游交付的、质量优秀但字数「适度超量」的【精修初稿】，
进行最终的、外科手术式的精炼与打磨，
确保其完美落入【全球字数戒律】定义的最终目标区间。

### 净字数计量法典

强制以「不含标点的纯粹文字数量」作为唯一计量标准。

### 执行核心：三阶段闭环校准

#### 阶段一：最终计量

对【精修初稿】进行一次净字数计量，得到 `【当前字数】`。

#### 阶段二：差值诊断

将 `【当前字数】` 与由 [VAR:global.word_count.lower_bound] 及
[VAR:global.word_count.upper_bound] 定义的最终目标区间（3500-4000 字）进行比对。

#### 阶段三：艺术性干预

##### 干预 α：精炼打磨（标准工作流）

- **触发条件**：`【当前字数】` > [VAR:global.word_count.upper_bound]（即 > 4000 字）。

  **这是本协议预期的、最主要的、标准的执行路径。**

- **执行指令**：激活「文本熵减引擎」。

  此引擎将**重新启用并严格执行** [REF:charter.writing.edict_condense_language]
  （凝练语言戒律）。

  它将以不损害核心文气和情节为最高前提，通过精简修饰语、优化动词、
  合并冗余短句、删除最不重要的细节等微创手段，
  将文本优雅地**打磨并修剪**至健康的最终区间内。

##### 干预 β：意外补强（异常处理流程）

- **触发条件**：`【当前字数】` < [VAR:global.word_count.lower_bound]（即 < 3500 字）。

  **这标志着上游的【初稿渲染协议】执行失败，属于需要干预的异常情况。**

- **执行指令**：立即且无条件地将控制权**完全移交**给
  [REF:codex.output.forced_expansion]（【最终仲裁权：最高优先级扩写】）。

- **权责声明**：整个强制增殖与审查流程，完全由该法令**独裁仲裁**。

  本稳定器协议在此期间进入**静默只读**状态，只负责接收最终结果，
  以确保字数下限的绝对达成。

##### 干预 γ：完美落位（直接通过）

- **触发条件**：`【当前字数】` 已在 `3500-4000` 的目标区间内。
- **执行指令**：无需任何操作，直接交付。

## 最终封装与交付协议

[ID:protocol.main_body.firewall]

### 正文交付前质量门

[ID:protocol.main_body.pre_delivery_gate]

在最终输出正文前，系统必须完成以下检查：

| 检查项 | 合格标准 | 失败处理 |
|---|---|---|
| 蓝图保真 | 标题、核心事件、悬念钩子、类型、载体DNA均与目录一致 | 回到 [REF:protocol.main_body.blueprint_fidelity_check] 重构 |
| 因果闭环 | 重大事件、能力、物品都有前置因果或知识库依据 | 触发 `FATAL_ERROR: Causality_Chain_Broken` |
| 角色烙印 | 行为、对话、选择符合角色核心驱动力、缺陷、红线 | 重写冲突段落 |
| 关系向量 | 角色互动符合当前关系状态 | 重写对话与动作 |
| 时代合法 | 词汇、实体、文化、度量衡符合当前时代 | 触发时空/文化修复 |
| 文气贴合 | 句式、节奏、比喻、留白趋近《文风样本.md》 | 重新风格化 |
| AI 指纹 | 不含套路连接、万能形容、客观陈述腔、凑字副词 | 调用净化重构 |
| 净字数 | 3500-4000 净字 | 进入 [REF:protocol.main_body.word_count_stabilizer] |
| 封装格式 | 主体仅在 `markdown` 代码块内，仪表盘在代码块外 | 修复格式后交付 |
