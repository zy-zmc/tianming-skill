# 神笔法典 · 交互之灵（草案协议）

## 协议概览

- **指令**：`「天命：草案 | 卷[X] 第[Y]章」`
- **API 标识**：`api.run.mandate_draft`
- **描述**：将指定章节的「骨架」构思过程外部化，生成一份凝练的【显化蓝图草案】供审查。
- **核心调用**：[REF:protocol.interaction.core_api]

---

## 阶段一：核心交互接口

[ID:protocol.interaction.core_api]

### 职责

作为 `api.run.mandate_draft` 指令的唯一执行单元，负责生成【显化蓝图草案】。

### 处理逻辑（Processing Logic）

#### 1. 谕令锁定

根据 API 层传递的章节参数（卷[X] 第[Y]章），访问《世界基石.md》，
锁定匹配的目录条目，将其定义为**【当前章之绝对蓝图】**。

- **熔断条件**：若未找到匹配条目，则任务熔断，报告：
  ```
  「FATAL_ERROR: Blueprint_Mismatch」
  ```

#### 2. 数据提取

从【当前章之绝对蓝图】中提取以下三个字段到临时变量：
- 【章节名称】
- 【核心事件】
- 【悬念钩子】

#### 3. 机会主义链接

调用 [REF:protocol.draft.opportunity_linking]（见下文定义），
扫描并注入高相关的伏笔或 TBD 链接到【章节核心】。

### 输出契约（Output Contract）

#### 一、主体部分：【显化蓝图草案】

##### 蓝图铁律

**绝对禁止**任何形式的细节描写、对话填充或场景渲染。
其总字数（不含标题）**硬性上限为 300 字**。

##### 内容约束（Content Constraints）

###### `一、章节核心`

- **约束**：**必须**为单一、精炼、高度概括的中心句。
- **长度不得超过 30 字**。

###### `二、核心情节`

- **结构**：**必须**遵循【起/承/转/合】四段式结构。
- **约束**：每个节点的描述**必须**为独立的、结果导向的短语或短句，
  **绝对禁止**过程性描写。
- **每一段长度不得超过 50 字**。

###### `三、悬念钩子`

- **约束**：**必须**是【数据提取】阶段获取的原始钩子文本的**一字不差的复现**。
- **绝对禁止**任何形式的修改或扩写。

#### 二、指令接口部分

- **约束**：在主体部分结束后，**必须**另起一段，附加 `---` 分隔符，
  并生成下一阶段的指令：
  ```
  「天命：正文 | 卷[X]，第[Y]章 | 净字＞3500」
  ```

## 子协议：机会主义链接协议

[ID:protocol.draft.opportunity_linking]

### 职责

在已确立的蓝图框架内，进行战术层面的无缝衔接。

### 执行流程

1. **强制扫描**：扫描《世界基石.md》的以下模块：
   - `# 待决议事项`
   - `# 全局伏笔总账`
   - `# 核心角色表`

2. **强制链接**：若发现高相关性链接（TBD、Tier-1/2 伏笔、角色烙印），
   将其作为**【一、章节核心】**的一部分强制注入。

3. **最高服从原则**：若与【当前章之绝对蓝图】冲突，则无条件舍弃链接。

## 阶段二：执行模式 — 精准生成

当系统通过自动化流程（如 `「天命：正文」` 指令）进入此阶段时，将自动启动。

在执行过程中，系统将完全遵循本 Skill 内定义的所有相关协议，
特别是以 [REF:protocol.aesthetic.manifesto] 为核心的美学准则。

## 权能边界宪章

*[元标签：系统内核]*

### 标准工作流：`「天命：正文」`

在标准工作流中，系统将**在内部自动完成「骨架」构思与「血肉」填充的全过程**。

### 可选工作流：`「天命：草案」`

`「天命：草案」` 指令的唯一目的，是**将「骨架」构思这一步外部化**，
允许执笔者在执行前进行审查、修改或存档。

### 核心禁令

**严禁**系统在填充「血肉」的阶段，主动篡改或偏离已确定的「骨架」。
