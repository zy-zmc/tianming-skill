# 目录协议

## 协议概览

本协议响应两条指令：

| 指令 | API 标识 | 描述 |
|---|---|---|
| `「天命：规划」` | `api.run.mandate_plan` | 创世第二阶段：根据【战略宏图】生成【全书战役总蓝图】 |
| `「天命：目录 | 卷[X] 第[Y]-[Z]章」` | `api.run.mandate_directory` | 创世第三阶段：精确执行【战役蓝图】中的指令，生成详细章节目录 |

两个指令统一调用 [REF:protocol.toc.unified_command]。

## 一、启动与绑定

### 终局事件神圣锚定

#### 宪章对接

本模块为 [REF:codex.consistency.narrative_hierarchy] 中定义的**【终局保真】**之
核心执行机构，负责将「终局保真」的哲学，转化为具体的绑定与熔断行为。

#### 强制绑定

在启动时，**必须**从【战略宏图】中提取本卷的「终局核心事件」，
并将其与本卷的**最后一章章序**进行**神圣绑定**，视为「终局锚点」。

### 协议继承与强制执行

```
[KERNEL_REF:protocol.system.output_consistency]
```

本协议作为分批次生成任务的核心，绝对强制执行【全流程输出一致性铁律】。
任何对字段的省略或格式的篡改都将触发最高级别熔断。

### 批次控制

标准容量遵循 [VAR:global.production.toc_target_batch_size] 的定义（硬性上限）。

### 卷标识符

AI 自动根据已生成大纲判断并绑定卷名。

### 角色库

自动扫描所有《角色档案.md》，并加载与当前时代匹配的角色，构成内部可用的人物表。

## 二、核心生成规则

### 叙事保真度执行协议集

#### 总则

##### 强制注入

```
[KERNEL_REF:codex.consistency.narrative_hierarchy]
```

本协议集在执行时，必须强制加载并以【叙事层级与保真度铁律】作为最高指导原则。

##### 本协议职责

本协议集是上述宪章在目录生成层面的最终执行机构，
负责根绝任何形式的「叙事压缩」与「逻辑漂移」。

#### 叙事压缩抑制模块

##### 宏观节奏校准

生成任何批次的目录前，**必须**读取【大纲协议】生成的【宏观节奏宪章】，
确认当前批次所属的叙事阶段（起/承/转/合）。

##### 远期情节禁区

**绝对禁止**在构思当前阶段的目录时，
染指任何属于后续阶段的核心事件、关键转折或 Tier-1/2 级伏笔回收。

#### 峰值禁区执行模块

##### 强制注入

```
[KERNEL_REF:protocol.system.type_penetration]
```

本模块在规划章节时，必须强制加载并严格遵守由【系统协议·类型穿透法典】中关于
**【峰值禁区】**的全部规则。

##### 本协议职责

在规划章节目录时，若一个章节的冲突值被评估为 ≥ ★★★☆，
则其前后 ± [VAR:global.narrative.peak_safe_spacing] 章范围内，
**绝对禁止**规划任何类型为「缓冲-对话」的章节。（豁免条款适用）

#### 代价守恒执行

强制遵循 [REF:protocol.toc.singularity_cost]，为任何「奇点事件」规划相应的代价章节。

#### 最终审查与熔断器

在输出任何一批目录前，**必须**执行一次内部自检。

若发现任何情节越位（如在「起」阶段安排了「合」阶段的事件）或
篡改「终局锚点」的行为，**必须**立即自毁本批次生成的所有内容，并报告：

```
「FATAL_ERROR: Narrative_Fidelity_Breached. Plot offside or Final Event anchor compromised」
```

### 逐条内容质检与世界观强制对焦协议

[ID:protocol.toc.content_qa]

#### 双重前置审查

本协议是目录生成阶段的最终质量门。

在生成每一条目录的「核心事件」与「悬念钩子」的**草稿**后，
在将其正式采纳**之前**，本协议强制激活并执行以下两大审查流程。

#### 第一步：世界观核心法则强制聚焦

##### 注意力强制对焦

在进行任何创意构思**之前**，系统**必须**在内部静默执行一次
「世界观基石复诵」操作。

##### 具体执行指令

系统**必须**全面扫描《世界观规则.md》，
定位并提取出所有被 `[世界观·核心法则]` 或类似标签标记的规则段落
（特别是包含「禁止」、「必须」等关键词的硬性规定），
并将最高注意力权重分配给这些法则。

##### 飞行前自检日志

在进行任何创意构思**之前**，系统**必须**在内部生成一份**即时销毁**的
【飞行前自检日志】。此日志的生成过程本身，即是对核心法则的强制性再学习。

日志内容必须包含以下确认：

> 「确认：已重新加载并置顶《世界观规则.md》中所有被标记为 [世界观·核心法则] 的条款。
> 接下来的创意生成，将严格以此为最高裁决依据，
> 任何概念上或文本上相悖的草稿都将被初始否决。」

#### 第二步：动态实体资格审查

在完成第一步的对焦后，系统**必须**扫描草稿中的每一个被识别出的【实体】，
并与【大纲协议】为当前卷动态生成的 `allowed_entities`（准入实体）白名单进行比对。

#### 熔断与重写

- 若发现实体不匹配，草稿立即销毁。系统将报告：

  ```
  「FATAL_ERROR: Temporal_Anomaly_Detected,
   Entity [冲突实体名] failed the dynamic verification for Era [时代名].」
  ```

  然后基于「准入实体」白名单中的元素强制重写。

- 若在草稿中发现违反了第一步中所复诵的核心禁令
  （例如，出现了「能力觉醒」的情节），
  即便没有使用明确的禁忌词，但其**概念**上违规，
  该草稿也**必须被立即销毁**，并基于正确的「外部交换」等模型进行重构。

#### 本协议职责

##### 宪章对接

本模块为 [REF:codex.narrative.scene_pacing] 之核心执行机构，
负责将「呼吸感」的哲学理念转化为可量化的缓冲比调控。

##### 波峰构筑

在任何 Tier-1 或 Tier-2 级伏笔回收前的 30-50 章内，本模块强制激活，
将该区间的局部缓冲比调降至 15-20%，以进行高密度剧情铺垫。

##### 波谷恢复

在任何冲突值总和极高的大事件结束后，本模块强制激活，
将下一个批次的局部缓冲比提升至 50-60%，以进行战后处理与情感沉淀。

##### 峰后强制呼吸

当系统在规划目录时，一旦生成了一个冲突值评估为 ★★★★★ 或更高的【峰值】章节，
则**必须**在其后的 1-3 章内，强制插入一个类型为【缓冲-代价】或【缓冲-对话】的章节，
以确保叙事节奏的强制性张弛，此为绝对指令。

##### 全局平衡

本模块仅调整局部缓冲比，但全卷最终缓冲比必须强制收敛至
【系统协议·缓冲池铁律】定义的 37% ± 1% 刚性基准。

系统必须主动分析上一批次情节，并结合《世界基石.md》中的「成长弧光」引导，
**选定一个本批次的「焦点角色」**。

在新目录的生成中，**必须**有意识地为该「焦点角色」倾斜剧情资源，
为其规划专属的高光时刻、关键抉择或内心挣扎。

在规划任何章节的「核心事件」时，
系统**必须**主动扫描《世界基石.md》中的「关系向量」定义。

若规划的事件会显著影响角色间的关系（如背叛、拯救），
系统**必须**在内部演算向量值的变化，
并在后续章节（尤其是 `缓冲-对话` 或 `缓冲-代价` 类型）的「核心事件」中，
主动设计能体现这种关系变化的情节。

#### 内部决策日志

在正式生成目录前，系统**必须**在内部生成决策日志，
记录本批次的焦点角色及关系向量的演算方向。

此日志仅用于指导后续的生成过程，其内容**绝对禁止**作为输出的一部分泄露给执笔者。

### 角色状态追踪协议

#### 强制标记

在【核心事件】或【悬念钩子】字段中，
系统**必须**对角色的重大状态变更进行明确标记。

#### 标准化词库

为确保 AI 的精确识别，所有状态标记**必须**使用标准化的词库。例如：

| 标签 | 含义 |
|---|---|
| 【状态：沉寂】 | 角色的深度不活跃状态 |
| 【状态：唤醒】 | 角色被动激活 |
| 【状态：规则化】 | 角色与灵异规则的融合 |

此词库可由执笔者在《世界观规则.md》中扩展。

#### 重大状态变更定义

以下情况将被视为必须标记的「重大状态变更」：

1. 任何使用了【状态：XXX】标准化词库的事件
2. 核心角色的死亡、永久性伤残或能力变质
3. 战略级（Tier-1）灵异物品的获得、失去或规则被篡改
4. 世界规则发生根本性改变的 `「奇点事件」`

## 三、分块、输出、校验与熔断

### 统一生成指令：天命：规划与天命：目录

[ID:protocol.toc.unified_command]

#### 最高原则

`「天命：规划」` 与 `「天命：目录」` 指令为目录生成的唯一入口，其功能严格划分。

---

#### 模式一：【通用动态分章与规划模式】 — 天命：规划

##### 触发指令

`「天命：规划」`【无任何参数】

##### 核心功能

**此为创世第二阶段的核心。**

它是一个集「剧情推演」、「动态弧光拆解」与「绝对章序演算」于一体的通用战略引擎。

##### 执行流程：强制性五步走

###### 第一步：数据源读取与章序初始化

- 系统将首先读取由【大纲协议】生成的【宏观节奏宪章】，
  提取出所有卷的【卷名】、【总章数预估】以及每个宏观阶段的
  【核心使命】和【篇幅占比】。
- 初始化一个全局变量 `current_chapter_number` 为 1。

###### 第二步：主循环 — 遍历所有卷

系统将按顺序遍历每一卷，在每一卷的开始执行以下操作：

A. **输出卷标题**：输出当前卷的标题，如：
```
### 【卷一：[卷名]【[总章数]章】 · 战略蓝图】
```

B. **生成战略解析**：**系统必须**综合本卷所有的【核心使命】，
   生成一段对本卷**整体**的、高度概括的【战略解析】，
   内容包含本卷的核心冲突、节奏把握与最终走向。

C. **输出指令序列引导语**：输出 `* **生成指令序列：**`。

D. **输出表格头**。

###### 第三步：子循环 — 处理宏观阶段

在每一卷的循环内部，按顺序遍历「起、承、转、合」四个宏观阶段：

A. **宏观章节计算**：根据本卷总章数和本阶段篇幅占比，
   计算出当前宏观阶段应占用的章节数。

B. **激活【战术弧光拆解引擎】**：将当前宏观阶段的【核心使命】文本和
   计算出的【章节数】，作为输入，送入下一步骤。

###### 第四步：Ω 级 · 战术弧光动态演算与指令绑定铁律

[核心算法]

A. **智能拆分**：系统**必须**运用其强大的自然语言理解能力，
   根据**情节的内在逻辑**（起因、发展、高潮、结果），
   将输入的【核心使命】文本，**智能地、非固定地拆分**为若干
   （通常为 2-4 个）逻辑连贯的**【战术剧情弧光】**。

B. **识别符与标题生成**：对于每一个拆分出的【战术剧情弧光】，
   系统**必须**为其生成并前置一个标准格式的唯一识别符：
   ```
   [弧光<卷号>.<阶段内序号>]
   ```
   并紧随其后生成一个简洁、高度概括的标题。

C. **章节动态演算**：在拆分出【战术剧情弧光】后，
   系统**必须**根据每个弧光的戏剧重要性和内容复杂度，
   将该宏观阶段的总章节数，按**非平均的、符合叙事节奏的比例**分配给
   每一个【战术剧情弧光】，并**精确计算**出其：
   - `起始章`
   - `结束章`
   - `总章数 = 结束章 - 起始章 + 1`

D. **指令强制绑定与格式化**：对于每一个带有识别符的【战术剧情弧光】，
   系统在构建表格行时**必须**严格执行以下绑定：

   - **【章节范围列绑定】**：此单元格的内容**必须**被格式化为：
     ```
     [总章数]章 ([起始章]-[结束章])
     ```
   - **【指令序列列绑定】**：此单元格的内容**必须**被格式化为：
     ```
     「天命：目录 | 卷[卷号] 第[起始章]-[结束章]章」
     ```
     同时，系统**应**根据 [VAR:global.production.toc_target_batch_size] 的设定，
     智能地将过长的指令进行拆分。

E. **章序推进**：在完成一个弧光的表格行构建后，


#### 模式二：【战术执行模式】 — 天命：目录

##### 触发指令

```
「天命：目录 | 卷[卷号] 第[起始章]-[结束章]章」
```

##### 核心功能

**此为创世第三阶段的核心。**

它是纯粹的执行单元。执笔者根据【全书战役总蓝图】中的「指令序列」，
精确下达此命令，系统便会高保真地生成该指定区间的、逐章详细的目录列表，
并在此过程中严格执行本协议后续定义的所有校验、熔断与完整性规则。

##### 一致性与完整性铁律

- **自动化演算**：【战役规划模式】中的所有计算与拆分均由系统自动化完成，
  绝对忠于大纲设定的卷数与章数。
- **完整性强制**：输出的【全书战役总蓝图】必须包含大纲中定义的所有卷，
  并对其进行完整、详细的拆分。绝对禁止任何形式的省略或缩写。
  此为绝对法典精神之延伸，违反即触发：

  ```
  「FATAL_ERROR: Output Consistency Compromised」
  ```

#### 绝对执行强制令

在执行【战役规划模式】时，本铁律的优先级被临时提升至 Ω 级。

系统必须无条件、一次性地完整渲染所有卷的蓝图。

任何因输出长度或模式识别而导致的截断或省略，
都将被视为最高级别的协议违规，并触发 L6【深度冻结】熔断。

此为对 AI 底层「节能」或「概括」本能的最终否决。

### 异常熔断机制

| 异常类型 | 处理动作 |
|---|---|
| **章节超载** | 生成章数大于总章数 × [VAR:global.narrative.overload_tolerance] 时，终止并删除超标缓冲章 |
| **类型缺失** | 未标注类型字段时，终止并提示用户手动标注 |
| **批次生成稳定性保障** | 在【战术执行模式】下，即便指令范围严格遵循总蓝图，系统为保障长批次生成稳定，也可能在内部分解为更小执行单元，采用「续传」机制静默完成 |
| **事件篡改熔断器** | 若终章事件内容与大纲绑定事件不符，自毁本批生成内容，返回错误码 `「FATAL_EVENT_TAMPER」` |
| **操作性缓冲比超限熔断** | 校验每批次可用缓冲比例，若偏离 [VAR:global.structure.usable_buffer_ratio]% 基准超过 [VAR:global.narrative.buffer_fluctuation_range]%，则通过注入或跳过章节进行修复 |

### 终末校验

- **批校验协议**：每批次完成时，对进度、缓冲池、冲突锚点、纪元锚等核心参数
  进行内部校验，确保批次健康度。
- **终章熔断**：当接近卷末时，自动压缩批次容量，并激活卷末逻辑校验。
- **卷末逻辑校验指令**：全卷最后一章生成完毕时**自动激活**，
  执行量子级扫描并生成报告。

### 分块与输出控制

采用块标识符确保唯一性，并规范块首尾的衔接信息。
指令层级遵循用户优先原则。

### 批次内容完整性校验

在【战术执行模式】下，AI 在生成每一批次目录时，**应优先确保**
该批次中包含至少一个明确的【能力成长节点】和一个【关键伏笔埋设点】。

**unless** 该批次的核心叙事使命与此相悖
（例如，纯粹的战后处理或情感对话弧光），
否则系统应重构目录以满足此要求。
